# 测试控制器使用说明

## 概述

`TestController` 提供了完整的测试接口，演示事件、监听器、Job以及它们结合使用的实际场景。

## 路由列表

所有测试接口都在 `/test` 前缀下：

### 1. 事件测试

#### 1.1 测试纯事件调用
```
GET /test/event
```
- **说明**：触发订单发货事件，演示纯事件调用
- **监听器**：`SendShipmentNotification`（已启用队列，异步执行）
- **返回**：事件触发状态

#### 1.2 测试事件触发多个监听器（混合：同步+异步）
```
GET /test/event-multiple?user_id=1001&email=test@example.com
```
- **说明**：触发用户注册事件，演示一个事件触发多个监听器
- **监听器**：
  - `SendWelcomeEmail` - 启用队列（异步）
  - `CreateUserProfile` - 启用队列（异步）
  - `InitializeUserSettings` - 同步执行（立即生效）
- **参数**：
  - `user_id`：用户ID（可选，默认：1001）
  - `email`：用户邮箱（可选，默认：test@example.com）

#### 1.3 测试订单创建事件
```
GET /test/event-order?order_id=2001
```
- **说明**：触发订单创建事件，演示混合场景
- **监听器**：
  - `UpdateInventory` - 同步执行（库存立即更新）
  - `SendOrderNotification` - 启用队列（异步发送通知）
- **参数**：
  - `order_id`：订单ID（可选，默认：2001）

### 2. Job测试

#### 2.1 测试纯Job调用
```
GET /test/job
```
- **说明**：直接调度Job任务
- **Job**：`SendEmail`
- **返回**：Job调度状态

#### 2.2 测试延迟Job
```
GET /test/job-delay
```
- **说明**：演示延迟5秒后执行的Job
- **Job**：`SendEmail`
- **延迟**：5秒

#### 2.3 测试指定队列的Job
```
GET /test/job-queue?queue=emails
```
- **说明**：演示指定队列执行Job
- **Job**：`SendEmail`
- **参数**：
  - `queue`：队列名称（可选，默认：emails）

#### 2.4 测试图片处理Job
```
GET /test/job-image?path=/uploads/image.jpg
```
- **说明**：演示图片处理Job
- **Job**：`ProcessImage`
- **参数**：
  - `path`：图片路径（可选，默认：/uploads/image.jpg）

#### 2.5 测试生成报表Job
```
GET /test/job-report?start_date=2024-01-01&end_date=2024-01-31
```
- **说明**：演示生成报表Job
- **Job**：`GenerateReport`
- **参数**：
  - `start_date`：开始日期（可选，默认：2024-01-01）
  - `end_date`：结束日期（可选，默认：2024-01-31）

### 3. 结合使用测试

#### 3.1 测试事件和Job结合使用
```
GET /test/combined?user_id=1001&email=user@example.com
```
- **说明**：演示事件和Job结合使用的完整场景
- **流程**：
  1. 触发 `UserRegistered` 事件（触发多个监听器）
  2. 同时调度独立的 `SendEmail` Job
- **参数**：
  - `user_id`：用户ID（可选，默认：1001）
  - `email`：用户邮箱（可选，默认：user@example.com）

#### 3.2 测试所有功能
```
GET /test/all
```
- **说明**：一次性测试所有功能
- **包含**：
  - 事件测试
  - Job测试
  - 事件+队列结合测试

## 查看执行结果

### 1. 查看日志

所有操作都会记录日志，可以通过日志查看执行情况：

```bash
# 查看应用日志
tail -f storage/logs/goravel.log
```

**日志示例**：
```
📧 [队列] 发送欢迎邮件给用户 ID: 1001, Email: test@example.com
📝 [队列] 创建用户档案，用户 ID: 1001
⚙️ [同步] 初始化用户设置，用户 ID: 1001
📦 [同步] 更新库存，订单 ID: 2001
🔔 [队列] 发送订单通知，订单 ID: 2001
📧 [Job] 发送邮件 - 收件人: user@example.com, 主题: 测试邮件, 内容: 这是一封测试邮件
```

### 2. 查看队列状态

如果使用队列（非sync模式），可以查看队列状态：

```bash
# 查看队列统计
go run . artisan queue:stats

# 查看失败任务
go run . artisan queue:failed
```

### 3. 启动队列监听器

如果使用队列，需要启动队列监听器：

```bash
# 启动默认队列监听器
go run . artisan queue:work

# 启动指定队列的监听器
go run . artisan queue:work --queue=emails
go run . artisan queue:work --queue=notifications
```

## 实际场景说明

### 场景1：用户注册流程

1. **触发事件**：`UserRegistered`
2. **监听器执行**：
   - `SendWelcomeEmail`（队列）：异步发送欢迎邮件
   - `CreateUserProfile`（队列）：异步创建用户档案
   - `InitializeUserSettings`（同步）：立即初始化用户设置

**优势**：
- 用户设置立即生效（同步）
- 耗时操作不阻塞主流程（异步）

### 场景2：订单创建流程

1. **触发事件**：`OrderCreated`
2. **监听器执行**：
   - `UpdateInventory`（同步）：立即更新库存（避免超卖）
   - `SendOrderNotification`（队列）：异步发送通知

**优势**：
- 库存立即更新，保证数据一致性
- 通知异步发送，不阻塞订单创建

### 场景3：事件+Job结合

1. **触发事件**：`UserRegistered`（触发多个监听器）
2. **同时调度Job**：`SendEmail`（独立任务）

**优势**：
- 事件用于业务解耦（一个事件触发多个操作）
- Job用于独立任务（不依赖事件系统）

## 注意事项

1. **队列配置**：确保 `config/queue.go` 中配置了正确的队列连接
2. **队列监听器**：如果使用队列（非sync模式），需要启动队列监听器
3. **数据库事务**：在事务中触发事件时，注意监听器的执行时机
4. **日志查看**：所有操作都会记录日志，便于调试和监控
